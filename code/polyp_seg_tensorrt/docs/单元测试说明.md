# 功能模块单元测试指南

单元测试用于**验证某个模块的功能是否正确**：在修改 Preprocessor、Postprocessor、Metrics 等模块后运行测试，可快速确认行为是否符合预期、是否引入退化，无需依赖 TensorRT/CUDA 或真实数据。

---

## 1. 测试目的与适用场景

| 目的 | 说明 |
|------|------|
| **功能正确性** | 验证模块在给定输入下输出是否符合约定（如 Letterbox 参数、Dice 公式、阈值行为）。 |
| **回归防护** | 修改预处理/后处理/指标逻辑后跑一遍测试，若失败则说明改动破坏了原有行为。 |
| **文档化行为** | 测试用例即“可执行的规格”：新成员可通过测试理解各模块的输入输出约定。 |

**何时跑测试**：修改 `include/*.hpp`、`src/Preprocessor.cpp`、`src/Postprocessor.cpp`、`src/Metrics.cpp` 或新增相关逻辑后，建议执行一次测试。

**不覆盖**：当前测试不包含 InferenceEngine（依赖 TensorRT/CUDA），引擎正确性通过锚点校验与验证集对比（见 `docs/Python与C++前后处理对照.md`）验证。

---

## 2. 构建

- 默认开启测试（`BUILD_TESTS=ON`），首次配置会通过 FetchContent 拉取 googletest（需网络）。
- **首次**启用测试时建议使用**空 build 目录**并显式指定生成器，避免 FetchContent 子构建与主项目生成器不一致：

```bash
cd /mnt/d/lk/code/polyp_seg_tensorrt
rm -rf build && mkdir build && cd build && cmake -G "Unix Makefiles" .. -DBUILD_TESTS=ON && make -j4
```

若平时用 Ninja，则用 `cmake -G Ninja .. -DBUILD_TESTS=ON`，之后不要在同一 build 目录切换生成器。

关闭测试：`cmake .. -DBUILD_TESTS=OFF`，再 `make`。

---

## 3. 运行

在 **build 目录**下执行：

```bash
# 推荐：通过 CTest 运行，失败时打印用例输出
ctest --output-on-failure

# 或直接运行测试可执行文件（可加过滤）
./bin/PolypSegmentationTRT_tests
./bin/PolypSegmentationTRT_tests --gtest_filter="Preprocessor.*"
./bin/PolypSegmentationTRT_tests --gtest_filter="Metrics.Dice*"
```

全部通过会看到 `100% tests passed`；若有失败，CTest 会列出失败的用例名，用 `--gtest_filter` 可只跑该用例便于排查。

## 4. 各模块测试用例说明

测试用例对应**某个模块在特定输入下的行为**，用于判断该模块功能是否有问题。

### 4.1 Preprocessor（`tests/test_preprocessor.cpp`）

| 用例 | 验证点 |
|------|--------|
| **ImageInfoLetterbox** | 给定原图尺寸，Letterbox 的 raw_w/raw_h、new_w/new_h、x0/y0 是否按 scale = 256/max(w,h) 与居中公式计算正确。 |
| **OutputBufferSize** | process 写入的 buffer 数值是否在合理范围（归一化后约 -2～2），无越界或未初始化。 |
| **SquareImageCenterPadding** | 原图已是 256×256 时，new_w/new_h 是否为 256、x0/y0 是否为 0（无 padding）。 |

若修改了 Letterbox 公式、归一化参数或 PIL 风格 resize，应跑上述用例确认未破坏约定。

### 4.2 Postprocessor（`tests/test_postprocessor.cpp`）

| 用例 | 验证点 |
|------|--------|
| **OutputShapeMatchesRawSize** | 在给定 ImageInfo（raw_w/raw_h/new_w/new_h/x0/y0）下，输出 mask 的尺寸是否为 raw_w×raw_h。 |
| **ThresholdBinary** | 对 0.6/0.4 交替的 prob 图，二值化后前景像素个数是否符合阈值 0.5 的预期。 |

若修改了裁边、阈值或还原原图尺寸的逻辑，应跑上述用例。

### 4.3 Metrics（`tests/test_metrics.cpp`）

| 用例 | 验证点 |
|------|--------|
| **DicePerfectMatch** | pred 与 gt 完全一致时 Dice 是否为 1。 |
| **DiceNoOverlap** | 无交集时 Dice 是否为 0。 |
| **DiceHalfOverlap** | 固定重叠关系下 Dice 是否为 0.5（公式 2*inter/(sum_p+sum_g)）。 |
| **DiceEmptyMasks** | 双方全为背景时约定是否为 1（避免除零）。 |
| **IoUPerfectMatch / NoOverlap / HalfOverlap** | IoU 在对应情况下的值。 |
| **ForegroundThreshold127** | 前景判定是否为 >127（与 Python 及文档一致）。 |

若修改了 Dice/IoU 公式或前景阈值，应跑上述用例。

## 5. 如何新增测试用例

1. 在对应 `tests/test_*.cpp` 中增加 `TEST(SuiteName, CaseName) { ... }`。
2. 用例内：构造输入（如 `cv::Mat`、`ImageInfo`、buffer），调用被测接口，用 `EXPECT_*` / `ASSERT_*` 检查输出或副作用。
3. 重新 `make` 后执行 `ctest` 或 `./bin/PolypSegmentationTRT_tests`。

示例（在 `test_metrics.cpp` 中增加一次 IoU 空 mask 约定）：

```cpp
TEST(Metrics, IoUEmptyMasks) {
    cv::Mat pred(10, 10, CV_8UC1), gt(10, 10, CV_8UC1);
    pred.setTo(0);
    gt.setTo(0);
    float iou = Metrics::calculateIOU(pred, gt);
    EXPECT_FLOAT_EQ(iou, 1.0f);
}
```

新增用例应**针对单一行为**、输入明确、预期可计算，便于日后该行为被改动时快速发现回归。
