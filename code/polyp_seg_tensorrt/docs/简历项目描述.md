# 简历项目描述（可直接复制修改）

---

## 项目名称

医学图像分割模型 TensorRT 部署与工程化验证

---

## 项目简介（1 句）

设计并实现从 PyTorch 导出到 C++ TensorRT 推理、Python/C++ 精度对齐、性能分析与四维压测的完整部署流水线，并沉淀为可复用的《部署流水线操作指南》，支持单帧 ~3.5ms、验证集 Dice 与 Python 端对齐、长时间压测无错误。

---

## 技术栈

PyTorch / ONNX / TensorRT / C++17 / OpenCV / CUDA；CMake 构建；Python 脚本负责导出、验证集准备与精度对比。

---

## 核心工作与成果（简历 bullet，可删减）

- **部署流水线设计**：梳理并实现「模型导出 → C++ 推理骨架 → 精度对齐 → 性能分析 → 压测与健壮性 → 文档」七阶段流水线，撰写《部署流水线操作指南》与一页纸清单，便于在类似项目中按阶段执行与排查。
- **精度对齐方案**：建立 Python 与 C++ 前后处理对照表；实现与 PIL 一致的 resize（像素级对齐），将验证集端到端 Dice/IoU 与 Python 差异控制在可接受范围；通过锚点校验（raw tensor MAE）与单图 debug 脚本保证中间结果一致。
- **性能与瓶颈分析**：实现三阶段计时（预处理 / 推理 / 后处理）与多轮 benchmark，定位瓶颈在 GPU 推理（约 73–80%）；文档化数据流、Host–Device 拷贝关系与 CUDA 流时间线，并给出双缓冲、流水线等优化方向。
- **四维压测与健壮性**：设计并实现吞吐与延迟（FPS、P99、按分钟 FPS）、显存稳定性（nvidia-smi）、热稳定性（长时间 FPS 观察）、异常输入抗压（空图、极端尺寸、全黑/全白）四维压测；对非法输入做统一校验，避免崩溃与 OOM。
- **可复现与文档**：整理推理流程与数据拷贝 Mermaid 图、单元测试（Preprocessor/Postprocessor/Metrics）、脚本与文档索引，支持他人复现与二次开发；具备开源准备（README/LICENSE/.gitignore 可补）。

## 面试可讲结构（3 分钟版）

1. **项目是什么**：医学图像（息肉）分割，从训练好的 PyTorch UNet 导出到 TensorRT，在 C++ 里做端到端推理；重点是**部署流水线完整、精度可验证、性能可分析、压测有方案**，而不是模型本身多新。
2. **我做了什么**：  
   - 导出：PyTorch → ONNX → TensorRT engine（FP16），约定输入 256×256、归一化与 Python 一致。  
   - 推理骨架：C++ 加载 engine、前处理（letterbox + PIL 风格 resize + 归一化）、H2D → enqueueV2 → D2H、后处理（裁边 + 二值化 + resize 回原图）。  
   - 精度对齐：前后处理对照表、锚点 bin 校验、验证集 Dice/IoU 对比；发现 resize 实现不一致导致差异，改 C++ 为 PIL 风格后对齐。  
   - 性能与压测：三阶段计时与 benchmark、四维压测（吞吐/延迟/P99、显存、热稳定、异常输入）、入口输入校验。  
   - 文档：部署流水线操作指南、推理流程与优化说明、性能瓶颈说明、一页纸清单。
3. **难点与收获**：  
   - 难点：Python PIL resize 与 OpenCV resize 像素映射不一致，导致 Dice 差一截；通过实现 PIL 风格 resize 并做单图/验证集对比解决。  
   - 收获：以后类似「模型转 C++ 部署」的项目，可以按《部署流水线操作指南》一步步做，知道每个阶段要产出什么、常见坑在哪。

## 可追问准备（面试官常问）

| 问题 | 可答要点 |
|------|----------|
| 为什么用 UNet？ | 息肉分割任务、数据量不大时 UNet 结构简单、易训练、易导出；输入 256×256 是速度与精度的折中。 |
| 精度对齐具体怎么做？ | 前后处理逐项对照（resize/letterbox/归一化/二值化）；锚点用 Python 导出 input/output bin，C++ predictRaw 后逐元素 MAE；验证集端到端 Dice/IoU；不一致时用单图 debug 定位到 resize，改 C++ 实现。 |
| 性能瓶颈在哪？如何优化？ | 瓶颈在 GPU 推理（约 73–80%）；可做 CPU–GPU 流水线（多线程 + 双缓冲）、H2D/D2H 与 kernel 重叠、或减小输入尺寸/批处理。 |
| 压测做了什么？ | 四维：吞吐与延迟（FPS、P99、按分钟 FPS）、显存是否泄漏、长时间是否降频、异常输入（空图/极端尺寸/全黑全白）是否崩溃；入口做尺寸与空图校验。 |
| 和 Python 的 Dice 差多少？ | 对齐后验证集 Dice/IoU 与 Python 差异在可接受范围（文档有实测）；对齐前因 resize 差异约 0.03，改后约 0.016。 |
